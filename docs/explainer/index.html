Mammogram U-Net Explorer

The exact network trained in CNN_tumor.ipynb: a U-Net whose encoder is EfficientNet-B0, taking one 256×256 grayscale mammogram in and producing one 256×256 probability map of "mass" out. Every number on this page was read from the live PyTorch model by src/model_inspect.py.

1. The shape of the network

A U-Net has two halves. The encoder (left side, going down) repeatedly shrinks the image while increasing the number of channels, so each cell of the deepest map summarizes a large patch of breast tissue. The decoder (right side, going up) grows the map back to full size. The dashed skip connections copy the encoder's higher-resolution maps straight across so the decoder can recover edges that the shrinking lost.

2. What a convolution does

A kernel is a small grid of numbers, the weights. The network slides it over the image. At every position it multiplies each pixel under the kernel by the matching weight and adds the products up. That single sum becomes one output pixel. The same nine weights are reused at every position, which is why a 3×3 kernel on a one-channel image costs only 9 learned numbers no matter how large the image is.

In the real model the first layer, encoder._conv_stem, has 32 kernels like the ones you can load above, each 3×3, applied with stride 2. So the very first thing the network does is halve the resolution: 256×256 becomes 128×128, with 32 channels. The pretrained kernels came from ImageNet (colour photos); because our input has one channel instead of three, the library summed the three colour kernels into one.

3. Pooling, and why this network has almost none

Pooling shrinks a feature map by summarizing each small window with one number. Max pooling keeps the strongest response in the window, average pooling keeps the mean. Classic U-Nets use 2×2 max pooling after every stage. Neither has weights; they are fixed rules.

EfficientNet makes a different choice. It has zero pooling layers in the encoder. It shrinks the map with stride-2 convolutions instead, which is a learned way to downsample: the kernel decides what to keep. Pooling appears only once per block, as a global average over the whole map inside the squeeze-and-excitation step (section 5), and the decoder grows the map back with nearest-neighbour interpolation, which is just pixel duplication.

4. Weights: what the 6.25 million numbers are

"Weights" means every number the optimizer is allowed to change. For this model that is the kernel values of all 91 convolutions, their biases where present, and the per-channel scale and shift of every BatchNorm. Training (Adam, 20 epochs) nudged all of them to make the Dice score go up.

The encoder's 4.0 million weights started from ImageNet pretraining and were fine-tuned. The decoder's 2.2 million started random and were learned entirely from 810 mammograms, which is one reason it is the part most likely to overfit. The segmentation head is a single 3×3 convolution from 16 channels to 1: 16 × 9 + 1 bias = 145 numbers decide the final mask.

5. Inside one encoder block (MBConv)

EfficientNet-B0 stacks 16 MBConv blocks. Each one is the same four-step recipe, and its efficiency comes from splitting a normal convolution into cheap parts. Here is block 1, the one that takes the map from 128×128 down to 64×64, with its real numbers.

6. Activations: SiLU in the encoder, ReLU in the decoder

After most convolutions the network applies a fixed nonlinear function to every value. Without it, stacking convolutions would collapse into one big linear filter. ReLU zeroes negatives. SiLU (also called Swish) is x · sigmoid(x), a smooth version that lets small negatives through; EfficientNet was designed with it. The sandbox in section 2 lets you apply either to a real convolution output.

8. Glossary

Kernel / filter
A small grid of weights (3×3, 5×5, or 1×1 here) slid over the input. One kernel produces one output channel.
Channel
One "layer" of a feature map. The input mammogram has 1; the bottleneck has 320. A conv with Cin inputs and Cout outputs has Cout kernels, each Cin×k×k.
Feature map
The tensor a layer outputs: channels × height × width. Early maps respond to edges; deep maps respond to tissue patterns.
Stride
How far the kernel steps between positions. Stride 2 halves the output size.
Padding
Zeros added around the border so the kernel can be centered on edge pixels. "Same" padding keeps the size; "valid" shrinks it by k−1.
Depthwise conv
One k×k kernel per channel, channels never mix. Spatial filtering at a fraction of the cost.
Pointwise (1×1) conv
Mixes channels at each pixel with no spatial context. 63 of this model's 91 convolutions are 1×1.
Pooling
Shrinking by taking the max or mean of each window. This encoder uses stride-2 convs instead; the only pooling is global average pooling inside squeeze-and-excitation.
BatchNorm
Normalizes each channel to zero mean and unit variance over the batch, then applies a learned scale and shift. Stabilizes training.
Squeeze-and-excitation
Average each channel to one number, pass through two tiny 1×1 convs and a sigmoid, and multiply each channel by the result. Lets the block turn channels up or down depending on the image.
Skip connection
Concatenating an encoder map onto the decoder map of the same resolution, so fine detail bypasses the bottleneck.
Receptive field
The patch of input pixels that influences one output value. Grows with depth; at the 8×8 bottleneck each cell sees most of the image.
Logits, sigmoid, threshold
The head outputs raw scores (logits). Sigmoid maps them to 0–1 probabilities. Pixels above 0.5 become the predicted mask that Dice is computed on.
Dice
2·|prediction ∩ truth| / (|prediction| + |truth|). 1 is a perfect mask, 0 is no overlap. Insensitive to the huge background, unlike pixel accuracy.
