Where the cost sits

MACs by stage

Measured time by stage

The decoder's share of MACs is the number to watch for the roadmap: it is trained from scratch on 810 images and it runs at the highest resolutions, so it is the natural first thing to shrink or freeze.
Kernel / filter
A small grid of weights (3×3, 5×5, or 1×1 here) slid over the input. One kernel produces one output channel.
Channel
One layer of a feature map. The input mammogram has 1 (or 3 identical ones for Mammo-CLIP encoders); the bottleneck has hundreds.
Feature map
The tensor a stage outputs: channels × height × width. Early maps respond to edges; deep maps respond to tissue patterns.
Stride
How far the kernel steps between positions. Stride 2 halves the output size. EfficientNet encoders downsample with stride-2 convolutions, not pooling.
Depthwise / pointwise conv
Depthwise: one k×k kernel per channel, channels never mix. Pointwise: a 1×1 kernel that only mixes channels. Together they replace a full convolution at a fraction of the cost.
Squeeze-and-excite (SE) gate
Each block averages every channel to one number, passes it through two tiny layers and a sigmoid, and multiplies each channel by the result (0–1). The Simulate tab shows these gates per image: which channels the block turned up or down.
Skip connection
Concatenating an encoder map onto the decoder map of the same resolution, so fine detail bypasses the bottleneck.
Receptive field
The patch of input pixels that can influence one cell of a feature map. Grows with depth; at the bottleneck one cell sees most of the image. Computed analytically from kernel sizes and strides.
MACs
Multiply-accumulate operations for one forward pass; the standard hardware-independent cost. One MAC ≈ two FLOPs.
Activation bytes
Size of every intermediate tensor the forward pass produces (float32). An upper bound on activation memory; the largest single tensor is what usually limits batch size.
Latency
Median wall-clock time of one forward pass, measured here on a laptop CPU. It is a relative number for comparing models, not a deployment figure.
Unused parameters
Weights present in the checkpoint that the network never executes (EfficientNet's final 1×1 head, which a U-Net encoder does not need). They cost download size, not compute.
Grad-CAM
A saliency map: the gradient of a chosen scalar (here, the mean logit inside a region) with respect to a stage's channels, used to weight those channels. Bright areas are what pushed the answer up.
Logits, sigmoid, threshold
The head outputs raw scores. Sigmoid maps them to 0–1 probabilities. Pixels above 0.5 are the predicted mask that Dice is computed on.
Dice / IoU
Dice = 2·|pred ∩ truth| / (|pred| + |truth|). IoU = |pred ∩ truth| / |pred ∪ truth|. Both ignore the huge background, unlike pixel accuracy.
Native vs cross-applied
Native: the model is run on the preprocessing it was trained with. Cross-applied: on a different one, to test how brittle it is.
Decoder untrained
Only the encoder of that model has learned weights. Its predicted mask is noise and is shown only so the encoder's feature maps can be compared; do not read its Dice.
